# plan-generator-bot

Telegram-бот, который составляет краткосрочные (поурочные) планы уроков и присылает их файлом DOCX.

## Что умеет

- `/start`: профиль учителя (Ф.И.О., школа, предмет, язык планов ru / kk / en, длительность урока).
- `/classes`: классы с количеством учеников (`7 А 25`).
- `/schedule`: недельное расписание (номер урока и класс по дням).
- `/plan`: выбор дня и урока из расписания (или любых классов), затем раздел, тема, цели с кодами, пожелания.
  Данные можно прислать одним сообщением:
  ```
  Раздел: ...
  Тема: ...
  Цели: 7.2.3.1 ...
  ```
- `/history`: прошлые планы, повторная отправка файла.
- Под каждым готовым планом кнопки: «Короче», «Больше заданий», «Другой вариант» и «Тот же урок: другой класс или дата». Последняя спрашивает только день и классы, а на экране проверки появляется «Тот же план без ИИ» (копия без обращения к модели).
- На экране проверки можно изменить дату, классы, раздел, тему, цели и пожелания.
- Меню команд (кнопка «/») регистрируется в Telegram при старте, если задан `BOT_TOKEN`.

Шаблон документа: шапка (раздел, школа, дата, педагог, класс, присутствуют / отсутствуют, тема, цели обучения, цели урока для групп «все / большинство / некоторые») и таблица «Ход урока» (этап и время, действия педагога и ученика, оценивание, ресурсы). Количество присутствующих считается по классам, «отсутствующих» остаётся пустым. Сумма минут по этапам всегда равна длительности урока.

## Как получить план в боте

1. `/start` один раз: Ф.И.О., школа, предмет (список кнопок), длительность урока.
2. `/classes` один раз: `7 А 25`, для 10–11 классов с направлением: `10 А 22 ЕМН` или `11 Б 20 ОГН`.
3. `/schedule` по желанию: по дням, строки вида `1 7А`, `2 7Б`.
4. `/plan`: день → урок из расписания (или классы) → раздел, тема, цели с кодами (можно одним сообщением:
   `Раздел: ...`, `Тема: ...`, `Цели: 1.1.1.1 ...`) → **учебник** (если загружен): страницы вручную (`22` или
   `22-23`), или «🔎 Найти по теме» → экран проверки → «✅ Составить план». Через 20–60 секунд приходит DOCX.
5. Под планом кнопки: «Короче», «Больше заданий», «Другой вариант», «Тот же урок для другого класса».

## КТП

`/ktp`: учитель присылает файл КТП в Word (`.docx` или старый `.doc`). Файл читает модель (OpenAI, структурированный
ответ, промпт на английском в `prompts/ktp-system.txt`): строки таблицы уходят частями по ~30 строк, части режутся
только перед строкой с номером урока, чтобы не разрывать урок. Берутся **общие колонки** (номер, тема, цели с
кодами, часы, дата; юнит необязателен, остальное игнорируется), названия колонок на русском, казахском и английском.
Текст копируется дословно, коды нормализуются (`4. 1. 1. 1` → `4.1.1.1`).

**Защита от искажений.** Каждая тема и каждый текст цели из ответа модели ищутся в тексте файла; чего в файле нет,
заменяется результатом обычного разбора кодом (с предупреждением). Число уроков, коды целей, итог часов и часы по
четвертям сверяются с разбором кодом и файлом. Если ИИ недоступен, файл разбирается кодом. Кнопка «Разобрать без
ИИ» показывает второй вариант. Цена около $0,02 за КТП на 68 уроков. `KTP_USE_AI=false` отключает модель.

Перед сохранением показывается сводка и замечания; затем выбираются классы, идущие по этому КТП.

В `/plan` для класса с КТП бот предлагает «Взять урок из КТП»: юнит → урок, и раздел, тема и цели подставляются
сами (на экране проверки можно выбрать другой урок). Урок КТП можно исправить в `/ktp` («5: новая тема» или
«5 цели: 4.1.1.1 текст»).

## Даты, календарь и вечерняя подготовка

- **Даты уроков.** После сохранения КТП бот расставляет уроки по датам: слот это день, когда у класса есть урок в
  `/schedule`, внутри четверти и не выходной. Если год уже идёт, бот спрашивает, какой урок КТП следующий. Даты из
  файла КТП используются, только если они есть у всех уроков. Уроки четверти занимают слоты этой четверти; что не
  поместилось, переходит в следующую, а бот пишет, сколько часов не хватает, и что можно сделать (доп. урок в
  `/schedule`, объединить уроки). Свободные слоты считаются резервом. Кнопка «📅 Даты уроков» в `/ktp` пересчитывает.
- `/calendar`: четверти, каникулы, праздники (2026–2027 заложены миграцией `V8`, переносы 2027 года проверьте по
  приказу). Свой выходной добавляется текстом («13.10 семинар», «12.10-14.10 больничный»), владелец (`ADMIN_IDS`)
  может добавить выходной для всех. После изменения даты уроков пересчитываются сами, так же как после изменения
  `/schedule`.
- `/week`: уроки недели с темами из КТП и отметкой ✅ у готовых планов. `/tomorrow`: предложение на ближайший день с
  уроками: темы, страницы книги (подбираются по теме, подтверждаются один раз и запоминаются в уроке КТП) и кнопки
  «Составить все», «Изменить урок» (привычный экран проверки), «Урок не состоялся» (остальные уроки сдвигаются).
  Параллельные классы с одним уроком получают один план.
- `/settings`: время (16:00–21:00) и режим вечерней подготовки: выкл, предложения (по умолчанию) или автомат (бот
  сам составляет планы и присылает файлы). Встроенный планировщик (`EveningJob`, каждые 5 минут) раз в день на
  учителя шлёт предложение на ближайший учебный день (в пятницу на понедельник); запись в `scheduler_runs` защищает от
  повтора после перезапуска. В праздник бот один раз предупреждает. Внешний пингер держит сервис на связи с 05:00
  до 23:45.
- Особые уроки: контрольная за юнит (20 минут), за четверть (40 минут), проект и CLIL получают свои указания в
  промпте (`LessonKinds`).

## Каталог книг и привязка к классам

`/books` показывает общий каталог (его видят все учителя бота): название, тип, класс, год, четверти и статус
страниц. Книгу добавляют **по ссылке на okulyk.kz**: бот читает страницу книги (название, авторы, издательство,
год, класс, число страниц, ссылка на PDF; у сайта нет API, читается одна страница по ссылке учителя), спрашивает
тип (Student's book / Workbook), для 10–11 классов направление и четверти.

В `/classes` у каждого класса кнопка «📚 Книги»: отмечаете книги, по которым ведёте класс. В `/plan` сначала
предлагаются привязанные книги (загруженные), а если привязок нет, то книги класса по номеру класса.

Если у привязанной книги нет страниц, бот ставит её в очередь и просит **владельца** одобрить загрузку (он видит
примерную цену, ≈ $0,005 за страницу). Владельцы задаются переменной `ADMIN_IDS` (по умолчанию первый id из
`ALLOWED_IDS`). Одобренные книги загружает утилита на компьютере владельца:

```
java -jar tools/book-ingest/target/book-ingest.jar --watch --env .env     # ждёт одобренных книг и грузит их
java -jar tools/book-ingest/target/book-ingest.jar --once --env .env      # один проход
java -jar tools/book-ingest/target/book-ingest.jar --book-id 5 --dry-run  # скачать PDF и посчитать страницы, без платных вызовов
```

Утилита скачивает PDF только по ссылке из каталога (https, okulyk.kz / okulyk.com), загружает страницы, ставит статус
«загружена» и, если задан `BOT_TOKEN`, пишет учителю, который просил книгу. Статусы: каталог → ждёт одобрения →
одобрена → загружается → загружена (или ошибка).

## Учебники (RAG без векторной базы)

Книги загружает `tools/book-ingest` (на своём компьютере: бот принимает файлы только до 20 МБ). Каждая страница
рендерится в картинку и **один раз** разбирается моделью с картинки: текст, упражнения с ключами ответов (для
открытых вопросов образцы), тексты для чтения, описания картинок. Страницы лежат в Postgres (`books`, `book_pages`).
При `/plan` бот находит страницы по номеру (печатному) или по теме и передаёт модели их данные.

```
./mvnw -f tools/book-ingest/pom.xml package
java -jar tools/book-ingest/target/book-ingest.jar --pdf book.pdf --title "Plus English Grade 7 Student's Book" \
     --subject "English language" --grade 7 --type student --quarters 1-4 --env .env
```

Параметры: `--type student|workbook`, `--track natural|social` (только 10–11 классы), `--quarters 1-4` (или `2`),
`--part "first half"`, `--from/--to`, `--pages 22,24,30-32` (перезагрузить конкретные страницы), `--parallel`.
Повторный запуск пропускает уже загруженные страницы. Цена порядка $0,005 за страницу (книга на 128 страниц ≈ $0,7).
Ключи ответов создаёт модель: открытые задания помечены образцами, аудирование без скрипта «ответа нет».

## Запуск локально

1. Создать бота у @BotFather, получить ключ OpenAI.
2. `cp .env.example .env` и заполнить значения (`ALLOWED_IDS` — Telegram id через запятую).
3. БД: любой Postgres (например Neon). Таблицы создаются Flyway в схеме `plangen`.
4. Запуск: `./mvnw quarkus:dev` (порт из `PORT`).
5. Чтобы Telegram достучался до локального бота, нужен публичный URL (туннель). Затем:
   `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook` с параметрами `url=<публичный URL>/webhook` и `secret_token=<WEBHOOK_SECRET>`.

## Деплой

Docker-образ собирается из `Dockerfile` (например, Render free). Переменные окружения как в `.env.example`, `PORT` задаёт платформа. Health check: `/q/health`.
