# plan-generator-bot

Telegram-бот для учителя: составляет краткосрочные (поурочные) планы уроков и присылает их файлом DOCX. Умеет читать КТП (календарно-тематический план), расставлять уроки по датам, готовить планы на завтра и брать задания из учебников.

## Быстрый старт: загрузка книги (`book-ingest`)

Бот сам книги не сканирует: после того как владелец нажал «Одобрить», страницы загружает утилита **на твоём компьютере**. Команды запускаются из корня проекта (нужен `.env` с актуальными `DB_URL`, `DB_USER`, `DB_PASSWORD`, `OPENAI_API_KEY`, `BOT_TOKEN`).

```bash
# 1. Проверка без платных вызовов: скачивает PDF и считает страницы (ничего не сохраняет)
java -jar tools/book-ingest/target/book-ingest.jar --book-id <ID книги> --dry-run --env .env

# 2. Загрузка страниц (платно: ≈ $0,005 за страницу, книга на 116 страниц ≈ $0,6)
java -jar tools/book-ingest/target/book-ingest.jar --book-id <ID книги> --env .env
```

`<ID книги>` виден в логах после одобрения (`book #4 approved`) и в `/books`. Если jar ещё не собран:

```bash
./mvnw -f tools/book-ingest/pom.xml package
```

Другие режимы:

```bash
java -jar tools/book-ingest/target/book-ingest.jar --watch --env .env   # ждёт одобренных книг и грузит их сам (окно держать открытым)
java -jar tools/book-ingest/target/book-ingest.jar --once --env .env    # один проход по всем одобренным книгам
```

Повторный запуск безопасен: уже загруженные страницы пропускаются и повторно не оплачиваются, упавшие дозагружаются. После загрузки утилита ставит книге статус «загружена» и пишет в Telegram учителю, который её просил. Подробности (ручная загрузка PDF, параметры) в разделе «Учебники».

## Как это устроено

```
Telegram ──webhook──▶ Render (Quarkus, этот проект) ──▶ Neon Postgres (схема plangen)
                              │
                              ├──▶ OpenAI gpt-5-mini  (планы уроков, чтение КТП)
                              └──▶ DOCX (Apache POI) ──▶ Telegram sendDocument

Ноутбук владельца: tools/book-ingest ──▶ OpenAI (vision, по странице) ──▶ тот же Postgres
```

- **Бот**: Quarkus 3 / Java 21. Telegram присылает обновления на `POST /webhook`; проверяются секрет (`X-Telegram-Bot-Api-Secret-Token`), список `ALLOWED_IDS` и дубли `update_id`. Ответ всегда `200`.
- **Состояние диалога** хранится в таблице `conv_state` (бесплатный хостинг засыпает и перезапускается), поэтому бот помнит, на каком шаге учитель.
- **Генерация** идёт в фоновом потоке без открытой транзакции БД: модель отвечает 20–60 секунд. Результат сохраняется и отправляется файлом.
- **Модель**: `gpt-5-mini` через LangChain4j со строгой JSON-схемой из Java-records. Все промпты на английском (дешевле), язык плана задаётся в профиле учителя (ru / kk / en).
- **Хостинг**: Render (бесплатный, засыпает; внешний пингер cron-job.org дёргает `/q/health` каждые 15 минут с 05:00 до 23:45), БД Neon (бесплатный Postgres).

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | профиль: Ф.И.О., школа, предмет, язык планов, длительность урока |
| `/classes` | классы и число учеников (`7 А 25`, для 10–11: `10 А 22 ЕМН` / `11 Б 20 ОГН`), кнопка «📚 Книги» у класса |
| `/schedule` | недельное расписание; по дню: 🗑 убрать урок, ↔️ перенести, ➕ добавить, ✏️ заменить день |
| `/plan` | составить план урока |
| `/ktp` | КТП: загрузить файл, юниты и темы, привязка классов, даты уроков |
| `/week`, `/next_week` | уроки этой и следующей недели по КТП, ✅ у готовых планов |
| `/tomorrow` | предложение планов на ближайший день с уроками |
| `/calendar` | четверти, каникулы, праздники, свои выходные |
| `/settings` | время и режим вечерней подготовки |
| `/books` | каталог книг, добавление из списка okulyk.kz или по ссылке |
| `/history` | прошлые планы, повторная отправка файла |
| `/instruction` | пошаговая инструкция по всем функциям (профиль, классы, расписание, КТП, книги, план, неделя, вечер, если что-то не так) |
| `/profile`, `/help`, `/cancel` | профиль, справка, отмена текущего ввода |

Меню команд (кнопка «/») регистрируется в Telegram при старте, если задан `BOT_TOKEN`.

## Как получить план

1. `/start` один раз, затем `/classes` и по желанию `/schedule`.
2. `/plan`: день → урок из расписания (или классы) → раздел, тема, цели с кодами. Можно одним сообщением:
   ```
   Раздел: ...
   Тема: ...
   Цели: 7.2.3.1 ...
   Пожелания: ...
   ```
   Если у класса есть КТП, бот предлагает «Взять урок из КТП»: юнит → урок, и данные подставляются сами.
3. **Учебник** (если загружен): страницы вручную (`22` или `22-23`) или «🔎 Найти по теме».
4. Экран проверки: можно изменить дату, классы, раздел, тему, цели, пожелания, книгу, урок КТП. «✅ Составить план», через 20–60 секунд приходит DOCX.
5. Под планом кнопки: «Короче», «Больше заданий», «Другой вариант», «Тот же урок: другой класс или дата» (последняя даёт копию без обращения к модели).

**Документ** по шаблону: шапка (раздел, школа, дата, педагог, класс, присутствуют / отсутствуют, тема, цели обучения, цели урока для групп «все / большинство / некоторые», ценность «Біртұтас тәрбие») и таблица «Ход урока» из трёх этапов (время, действия педагога и ученика, оценивание, ресурсы). Сумма минут равна длительности урока. Для нескольких классов присутствующие считаются по классам. В план включены задания с ИИ. Цели обучения и коды вставляются дословно из КТП или от учителя, модель пишет только цели урока и ход урока. Имя файла: `plan-дата-класс-тема.docx`.

## КТП

`/ktp`: учитель присылает файл КТП: Word (`.docx`, старый `.doc`) или PDF с текстовым слоем (скан без текста не читается).

1. **Класс.** Бот всегда спрашивает, для какого класса КТП; для 10–11 классов ещё и направление (ЕМН / ОГН).
2. **Чтение.** Файл читает модель (`prompts/ktp-system.txt`, дословное копирование): для Word строки таблицы уходят частями по ~30 строк, для PDF строки текста с позицией x (по ней видна колонка) частями по ~240 строк. Части режутся только перед номером урока, чтобы урок не разорвало. Берутся общие колонки: номер, тема, цели с кодами, часы, дата; юнит необязателен. Названия колонок на русском, казахском и английском. Коды нормализуются (`4. 1. 1. 1` → `4.1.1.1`).
3. **Защита от искажений.** Каждая тема и текст цели из ответа ищутся в тексте файла. Для Word чего нет в файле, заменяется результатом разбора кодом; при расхождении кодов целей берутся цели из разбора кодом. Сверяются число уроков, итог часов и часы по четвертям. Для PDF разбора кодом нет, поэтому только проверка по тексту файла и замечания. Если ИИ недоступен, Word разбирается кодом (кнопка «Разобрать без ИИ»). `KTP_USE_AI=false` отключает модель (PDF тогда не читается).
4. **Часы.** Урок КТП на несколько часов при сохранении разбивается на отдельные уроки по 1 часу (3 часа дают 3 урока с тем же текстом и пометкой «(2/3)»), у каждого своя дата в расписании. В промпте для модели такой урок получает указание, какой он по счёту из серии: первый вводит тему, последний закрепляет. Правка темы или целей урока меняет все его часы.
5. **Проверка.** Бот показывает сводку (уроков, часов, юнитов, четверти, контрольные, замечания). После «Верно, сохранить» выбираются классы.
6. **Управление.** `/ktp` показывает для каждого КТП: класс, уроков и часов, часы по четвертям, привязанные классы, диапазон дат, ближайший урок. Кнопки: «🔗 Классы» (привязать КТП к классам: один КТП ведут несколько классов, класс идёт по одному КТП), «📅 Пересчитать даты», «🔄 Даты заново с начала года», «✏️ Исправить урок» («5: новая тема» или «5 цели: 4.1.1.1 текст»), «🗑 Удалить».

Цена разбора: около $0,02–0,03 за КТП на 68 уроков. Сохранение КТП того же класса и направления заменяет прежний.

## Даты, календарь и вечерняя подготовка

- **Даты уроков.** Слот это день, когда у класса есть урок в `/schedule`, внутри четверти и не выходной. Даты всегда считаются с первого дня учебного года и первого урока КТП, поэтому прошедшие уроки получают даты в прошлом (считаются проведёнными). Уроки четверти занимают слоты этой четверти; не поместившееся переходит в следующую, а бот пишет, сколько часов не хватает и что можно сделать (доп. урок в `/schedule`, объединить уроки). Свободные слоты считаются резервом. Даты из файла КТП используются, только если они есть у всех уроков, и при пересчёте не двигаются.
- **Пересчёт** идёт вперёд от сегодня и запускается сам после изменения `/schedule`, `/calendar` и после «Урок не состоялся». Подготовленные, проведённые и прошедшие уроки не двигаются. Если КТП загружен раньше расписания, после сохранения расписания бот предлагает «Расставить даты».
- **`/calendar`.** Четверти и праздники 2026–2027 заложены миграцией `V8` (переносы 2027 проверьте по приказу). Свой выходной добавляется текстом («13.10 семинар», «12.10-14.10 больничный»); владелец (`ADMIN_IDS`) может добавить выходной для всех.
- **`/week` и `/next_week`**: уроки недели с темами из КТП и отметкой ✅ у готовых планов, кнопка переключения недели.
- **`/tomorrow`**: предложение на ближайший день с уроками: темы, страницы книги (подбираются по теме, подтверждаются один раз и запоминаются в уроке КТП) и кнопки «Составить все», «Изменить урок», «Урок не состоялся» (остальные уроки сдвигаются). Параллельные классы с одним уроком получают один план.
- **`/settings`**: время (16:00–21:00) и режим: выкл, предложения (по умолчанию) или автомат (бот сам составляет планы и присылает файлы; платно). Встроенный планировщик (`EveningJob`, каждые 5 минут) раз в день на учителя шлёт предложение на ближайший учебный день (в пятницу на понедельник), в праздник предупреждает один раз; запись в `scheduler_runs` защищает от повтора после перезапуска.
- **Особые уроки.** Контрольная за юнит (20 минут), за четверть (40 минут), проект и CLIL получают свои указания в промпте.

## Каталог книг и привязка к классам

`/books` показывает общий каталог (его видят все учителя бота): название, тип, класс, год, четверти и статус страниц.

- **Выбор из списка okulyk.kz.** Кнопка «🔎 Выбрать из списка okulyk.kz» показывает книги вашего предмета для выбранного класса (один запрос к странице класса на okulyk.kz, список держится 6 часов) и рядом с каждой статус: нет в базе, в каталоге, ждёт загрузки, загружена. Нажатие на номер добавляет книгу.
- **По ссылке.** Бот читает страницу книги (название, авторы, издательство, год, класс, число страниц, ссылка на PDF; у сайта нет API), спрашивает тип (Student's book / Workbook), для 10–11 классов направление и четверти.
- **Без дублей.** Ссылки сравниваются нормализованно, а книга с тем же названием, классом и типом повторно не создаётся: страницы одной книги сканируются один раз.
- **Привязка к классам.** В `/classes` кнопка «📚 Книги» отмечает книги, по которым ведётся класс. В `/plan` сначала предлагаются привязанные загруженные книги, иначе книги по номеру класса, направлению и четверти.
- **Загрузка.** Если у привязанной книги нет страниц, бот ставит её в очередь и просит владельца одобрить (видна примерная цена). Владельцы задаются `ADMIN_IDS` (по умолчанию первый id из `ALLOWED_IDS`). Статусы: каталог → ждёт одобрения → одобрена → загружается → загружена (или ошибка). Загрузку делает утилита `book-ingest` (см. начало документа).

## Учебники (RAG без векторной базы)

Книги загружает `tools/book-ingest` на своём компьютере (бот принимает файлы только до 20 МБ). Каждая страница рендерится в картинку и **один раз** разбирается vision-моделью: печатный номер, текст, упражнения с ключами ответов (для открытых вопросов образцы), тексты для чтения, описания картинок. Страницы лежат в Postgres (`books`, `book_pages`). При `/plan` бот находит страницы по номеру или по теме (поиск по словам без эмбеддингов) и передаёт модели их данные; модель цитирует упражнения со страницей, а точные ключи подставляет код.

Ручная загрузка PDF:

```bash
java -jar tools/book-ingest/target/book-ingest.jar --pdf book.pdf --title "Plus English Grade 7 Student's Book" \
     --subject "English language" --grade 7 --type student --quarters 1-4 --env .env
```

Параметры: `--type student|workbook`, `--track natural|social` (только 10–11 классы), `--quarters 1-4` (или `2`), `--part "first half"`, `--from/--to`, `--pages 22,24,30-32` (перезагрузить конкретные страницы), `--parallel`, `--force`, `--dry-run`. Утилита скачивает PDF только по ссылке из каталога (https, okulyk.kz / okulyk.com). Ключи ответов создаёт модель: открытые задания помечены образцами, аудирование без скрипта «ответа нет», ключи стоит проверять.

## Деплой

Docker-образ собирается из `Dockerfile` (Render free). Переменные окружения как в `.env.example`, `PORT` задаёт платформа. Health check: `/q/health`.

**Вебхук.** Привязан к токену бота. После выпуска нового токена его надо зарегистрировать заново (подставь свои значения, `secret_token` равен `WEBHOOK_SECRET` на Render):

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" -d "url=https://<сервис>.onrender.com/webhook" -d "secret_token=<WEBHOOK_SECRET>"
curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"
```

`getWebhookInfo` показывает `url`, число необработанных сообщений и `last_error_message`.

**Пингер.** Бесплатный Render засыпает: задание в cron-job.org на `https://<сервис>.onrender.com/q/health` по расписанию `*/15 5-23 * * *` держит сервис на связи.

## Локальный запуск

1. Создать бота у @BotFather, получить ключ OpenAI.
2. `cp .env.example .env` и заполнить значения (`ALLOWED_IDS`: Telegram id через запятую).
3. БД: любой Postgres (например Neon); таблицы создаёт Flyway в схеме `plangen`.
4. Запуск: `./mvnw quarkus:dev` (порт из `PORT`, по умолчанию 3847).
5. Чтобы Telegram достучался до локального бота, нужен публичный URL (туннель), затем `setWebhook` как выше.

Сборка без тестов: `./mvnw -q clean package -DskipTests`.

## Правила разработки

Тестов в проекте нет и не добавляются (ни unit, ни интеграционных, ни с Testcontainers). Запросы к платным API ради проверок не делаются: платные вызовы только по явной просьбе владельца. Подробности и структура кода: `CLAUDE.md`.

## Известные ограничения

- КТП из PDF только с текстовым слоем; тема урока в PDF иногда укорачивается, поэтому смотрите экран проверки.
- Двухчасовой урок занимает два слота, но хранится одной строкой: при пересчёте на границе «вчера и сегодня» его второй слот может занять другой урок.
- Праздники 2027 года с переносами нужно проверить по приказу и добавить в `/calendar`.
